# 9 October 2026: overnight alert investigation

## Evidence and confidence

Sanitized Caddy log analysis for 00:00 through 09:00 UTC counted 701 responses
in the 5xx range. Of these, 675 carried malformed Next-Router-State-Tree headers.
Web logs independently show the router-state parser exception. The pattern is
consistent with automated malformed-request scanning; it does not establish an
actor or a successful compromise. Other failures included 12 root-page 502s and
10 agents-API 503s. The guard addresses the confirmed dominant cause, not every
possible source of 5xx.

HTTP 200000 was a monitor formatting bug: curl printed HTTP 200, then failed
while receiving the body; the fallback appended 000. This was a real transport
failure, not an HTTP status or proof of success.

Reference quote observations show roughly eight-second timeouts around 03:42,
03:48 and 03:54 UTC. Sellers had not restarted overnight. Shared-host or network
pressure is plausible but not proven as their cause. Failed first-party checks
were retried only after ten minutes, letting last-good observations age past the
alert threshold. No Marque-intent paid job was created in the overnight window.

## Verified changes (live 10 October 21:36 UTC)

The first preview caught an important implementation trap: Next removes Flight
headers before invoking middleware, so a middleware-only check did not reject
the actual malformed RSC request. Caddy now supplies a trusted header mirror,
discarding any client-supplied mirror and normalizing duplicate state headers to
the same value. Only the loopback-bound web upstream uses this rule; seller
routes are unchanged. The deploy and rollback renderer retain the rule. See
[Caddy header handling](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy#headers).

- Reject invalid router-state headers, unsupported Server Actions and control
  characters in paths before rendering. Preserve valid App Router navigation.
- Separate HTTP status from curl transport outcome; keep timeout failures visible.
- Monitor lightweight liveness and the full status page; include Tidemark. Bound
  status-page dependency waits without reporting failures as healthy.
- Retry failed first-party quote probes after one minute, healthy checks at ten.
  Preserve failed observations, third-party cadence and alert thresholds.
- Add a public Activity tab and aligned mobile comparison columns, shared by the
  comparison page and marketplace sheet.
- The standalone comparison previously resolved capabilities for up to 300 agents
  before selecting two or three, even on an empty comparison. Browser verification
  reproduced a response still unfinished after 20 seconds. Selection now precedes
  enrichment; an empty comparison does no market lookup. Already-decoded query
  values are bounded and deduplicated without a second URI decode.

## Verification

The proxy-level regression now passes 11 cases: normal pages and valid RSC return
200; malformed, empty or structurally invalid routing state, unsupported actions
and control-byte paths return 400. A spoofed mirror cannot bypass validation;
a client mirror without an original state header is discarded.

Additional read-only observation: Keel's stored MCS result 11588 has a dependency
timeout response, so its required answer fields are absent. It is not a returned
wrong arithmetic answer and remains a published failed result. A later RPC head
sample found four configured providers answering successfully, one returning
JSON-RPC error -32001 and one transport failure. This does not prove which
provider caused that historical timeout. No RPC configuration, seller runtime,
test tolerance or historical result was changed as part of this patch.

reversible blue/green slot at 21:36 UTC on 10 October. Its first deployment
