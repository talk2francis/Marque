## Additional findings beyond the pack

1. **A0, claim identity binding:** `apps/web/lib/claim.ts::verifyClaim` verifies nonce/tokenId/owner but signs caller-supplied `args.agentId` into its claim token without matching the canonical identity key. A mocked local owner proof for token 1 successfully authorized agent ID 999. `claim/publish::POST` selects only the caller-named indexed agent and does not compare row identity/registry/chain to the proof. Never reproduce against production. Derive the agent key from verified chain/registry/token, validate all identifiers at publish, reread ownership immediately before mutation.
2. **A0, publish drift and replay:** `claim/publish::POST` hardcodes `chainId:56` and `/agents/56/...` despite a 56/97 claim model; it performs no new `ownerOf` read after the 20-minute claim token was issued. Its conflict update leaves old owner/proof fields, and listing/category writes are separate transactions. Use the existing rail with chain-correct identity checks, atomic writes and meaningful retry idempotency; retain prior proof observations.
3. **A0, signed expiry inconsistency:** `quote.ts::verifyNegotiation` checks `neg.response.quote_expires_at`; `description.ts::buildDescriptionContent` signs a top-level `quote_expires_at` first when present. A locally signed envelope whose signed top-level expiry is past, but response expiry is future, is accepted. Treat this as part of the expiry slice, preserving SDK canonicalization. Validate one authoritative signed expiry and reject conflicting representations. The pack's assumption that signed expiry is uniformly stricter is incomplete.
4. **A0, cached ready state:** `commerce/src/supply.ts::commercialStates` uses two-hour observation age, not `quote_expires_at`, to promote `ok=true` to hireable/settleable. Local expired stored-quote fixture remains hireable. Keep observation history separate from a presently purchasable quote; `hire.ts::createIntent` already rejects stored quotes within 20 seconds of expiry and must be retained.
5. **A0, payment-label mismatch:** owner GET returns `jobsPaid` from `funded_raw IS NOT NULL`, not PaymentReleased. For Plinth the sampled owner API says 10 while the marketplace's settled count says 3. These are different populations/states; neither is evidence of ten released payments. Add clear funded/paid fields and compatibility treatment rather than silently redefining the old field.
6. **A0, stale-cache provenance:** `apps/web/lib/phase2-api.ts::served` returns `cachedProjection.value` and discards its `stale/ageMs/computedAt` metadata. Last-good fallback can outlive the API's apparent 15-second cache freshness. Add compatible provenance headers/fields and bounded stale semantics.
