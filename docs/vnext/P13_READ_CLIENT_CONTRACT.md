# Read client and payment inspection contract

Source preparation is isolated while P12 validates; P12 is not declared complete early. P13 final validation follows its completed checkpoint. Existing P07 catalog/unsigned plan, P06 receipt/content/chain replay, P03 seller guide and current docs shell are reused. No replacement SDK, registry, hosting product, payment primitive or API tier.

Browser-safe `@marque/commerce/read-only` exposes existing typed catalog GET and pure unsigned plan plus `inspectPaymentChallenge`. Node-only `@marque/execution/evidence` exposes existing sorted-JSON SHA-256 receipt checks. Separate `examples/read-client` imports package subpaths without database, wallet or signing configuration. These are local checkout packages, not a publicly published npm release; Node uses the existing TypeScript loader. Caller must review expected selections independently. No source signature replay, current ownership, simulated success, independence or paid work is inferred from a syntactic plan or content hash.

Pure captured-response schema `marque.payment-challenge-inspection.v1`, beta/read-only: numeric v1 body or numeric v2 PAYMENT-REQUIRED header, bounded HTTP capture, at most16offered options. Amounts stay canonical uint256 strings. BSC56/97 CAIP-2 labels are distinguished from unsupported networks/legacy aliases; no guessed chain, ticker, decimals or dollar value. Missing/contradictory amount, malformed/null/huge requirements, duplicate headers, conflicting body, bad UTF8/encoding and unsafe v2 resource shape fail. MPP/mixed challenges remain unsupported. All options retained; none selected automatically. Optional caller-reviewed chain/asset/payee/raw cap comparison is declared-terms comparison only. Authentication/token support/absolute expiry/replay/idempotency/settlement stay unproven; relative maxTimeoutSeconds is never absolute quote expiry. executionAllowed alwaysfalse. No fetching, credentials, wallet, signing, authorization or retry.

The existing legacy `parseChallenge` remains a compatibility display parser, not the new verification API or an atomic amount parser. It no longer strips arbitrary characters into numbers; malformed network text cannot become a numeric chain. No stored receipt or response is rewritten. New machine consumers use the explicit versioned inspector.

Concrete discovered defect: old x402 quote treated every non402 response, including404/503 and discovery200, as free, and its preflight/execute POSTed tasks without a qualified adapter. Observed selected endpoints returned200discovery/404/503. The minimal repair keeps one unsigned guarded GET for observation, returns unknown price/payment-required or failure, never infers free task compatibility, and blocks task preflight/execute before network. Existing ERC-8183 quote/hire, provider binding, seller SDK0.5.5/buyer0.6.0 and buyer signing are unchanged. Probe recognizes structured v2 header requirements; version marker alone is not a parseable challenge. Reachability remains separate from authenticated payment compatibility. This deliberately restricts an unproven legacy task rail; rollback must not silently re-enable unsafe POSTs or free-price claims.

No dependency/lock/ABI/migration changes. Added package subpaths and static example schema are additive; default marketplace/phase2/receipts APIs remain. No public npm publishing, agent invocation, offchain signature, wallet session, onchain transaction or production deploy is authorized or performed.
