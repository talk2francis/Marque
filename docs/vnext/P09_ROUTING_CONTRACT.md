# Catalog suitability diagnostics v1

P09 implements the explicit insufficient-supply fallback. This is a local inspection library and CLI, not a proven recommendation engine or a deployed routing service. Catalog v1 has no authenticated exact-task acceptance, exact-service quality binding, endpoint commitment, current owner proof, confirmed settlement history or action charter. Therefore every candidate is REJECTED or UNKNOWN; eligibleSelections is empty, recommended=null, autoHire=false and state=insufficient_comparable_supply. A category match, stored quote, identity-level test pass or known historical paid job cannot silently fill those gaps.

`@marque/commerce/routing` exports strict routingIntentSchema, routingInputSchema and pure explainCandidates. Input schema marque.routing-input.v1 carries the existing machine catalog v1 unchanged, an explicit UTC asOf, category from the existing catalog enum, task text, action chain56/97, exact token-address/decimal/raw-integer budget and an ordered distinct objectives list. It reuses SDK task-text sanitization and labels its Keccak text commitment separately from quote envelope, negotiation, description, receipt and artifact hashes. It is not an authenticated task acceptance. No LLM, network, wallet, signing, DB or implicit wall clock.

The complete parsed intent and exact selected agent/service/provider/identity-chain/action-chain tuple are inspectable. Duplicate selections, mismatched identity fields, missing services, category/action-chain mismatches and unavailable escrow quotes retain rejection reasons. First-party flag keeps its INDEXED_AND_CONFIGURED provenance, never authenticated human control. No fallback provider is substituted; all supplied rows, including failures, remain visible.

Source freshness is recomputed at asOf, ignoring the cached sourceAgeMs. Null, stale flag, future over30seconds or older than5minutes is stale/unknown. This5minute diagnostic policy does not alter existing quote acceptance, MCS freshness or API caching. Future source within30seconds is explicit clock-skew allowance. Expired price or expiry at asOf is rejected; unknown dates stay unknown. Observations from the future beyond30seconds, invalid/zero/unbounded amounts and accepted lifetime over900seconds are rejected. No stale source or expired quote yields an inspection price.

Price comparison uses BigInt only with matching action chain, token address and decimals. Symbol equality alone is insufficient. No floating-point conversion, USD rate, gas estimate, cross-token normalization or permit assumption. Current stored unsigned quotes remain identity_matched_unsigned observations; nothing here cryptographically replays them or authorizes hire. A matched price can say within/over budget while task suitability still remains UNKNOWN.

The requested objectives are disclosed in inspectionOrder: price compares available compatible stored prices, unknown last; fresh_usable_evidence, confirmed_settlement and least_authority have no adequate catalog-v1 evidence and tie without imputation. Final tie break is ASCII lowercased agent/service/provider selection key then deterministic JSON serialization of the parsed output. First-party status never adds preference. This is an **inspection order, not a qualified-provider ranking**; even a cheap first entry can be rejected for category mismatch. No aggregate trust score, best provider, latency winner or user-facing recommendation is produced. Existing marketplace sort semantics are unchanged.

Counts explicitly distinguish supplied page entries and catalogTotal; offset/hasMore/population mismatch marks incomplete. These are catalog entries, not independent operators or all current supply. No entries/one entry/duplicates/partial pages deterministically retain insufficient_comparable_supply. manualBrowse points to the existing /register category route, contains no task text, and never initiates a quote, free task or hire.

Run `node --import tsx scripts/explain-candidates.mts LOCAL_INPUT.json`. The CLI reads a local regular UTF-8 JSON file capped while reading at2MiB. It shares scripts/lib/local-json.mts with P08's unchanged replay behavior. JSON input/output can contain private task text: retain it locally; there is no telemetry/upload. Unknown schema/oversized/malformed/non-UTF8 input exits1 with redacted error and no stdout. Exit0 means diagnostics succeeded, not that any candidate is qualified. The library version is new/additive; no HTTP endpoint, existing API change, package/SDK dependency, migration, worker, contract or UI component is added.

Restore full evidence routing only when at least two genuine adequate exact-task providers are established through current owner/service/endpoint and quote commitment checks, fresh usable task evidence, authenticated operator/consent diligence, actual scoped chain settlement and supported authority inspection. Reuse P05/P06/P07 portable evidence and unsigned plans; do not introduce unverifiable booleans as proof. Even then never auto-hire. Paid activity, chain writes, new authority and production release keep their separate gates. Rollback is source-only; no database rows or observations change.
