# Read-model maintenance, 13 November 2026

Release 6273b25 passed functional acceptance and deployment, but [external run 43452766214](https://github.com/talk2francis/Marque/actions/runs/43452766214) still failed latency at 25 peak visitors before the hold. Page p95 was 8,717 ms and API p95 11,005 ms, with no completed HTTP errors or persistent restarts. No higher stage ran. Capacity remains unestablished and Adopt publication stays withheld.

Further read-only diagnostics distinguished small exact reads from broad materialization. Sampled job-history readers took 56 to 132 ms, reference live terms 97 ms, and a cold catalogue function 2,615 ms. These sequential source timings are not capacity measurements. A minimal compiled-worker diagnostic returned all fourteen reads successfully: the first seven-request burst took up to 3,172 ms and its repeat up to 815 ms. The worker had a CPU cap, its own Redis, copied existing observations and a CPU profiler; these timings cannot establish production throughput. Traces with intrusive hooks or malformed direct-worker redirects were rejected as diagnostic failures, not counted as acceptance.

The catalogue plan also underestimated final candidate cardinality. A broad join override timed out and was rejected. A narrower identity-join prototype preserved the complete mainnet and practice rows but had variable, modest gains; it was not implemented. No optimizer setting or eligibility predicate changes in this candidate.

The keyless MCP process now maintains ordinary public read models between visitors. It performs its normal readiness bootstrap, then reads catalogue views on both networks, the combined Ready view, all three evidence ladders, proof, funnel, coverage and live examples. Two reads run at a time; every body must complete within ten seconds. The next pass starts five seconds after the previous pass finishes. Failures are reported and cancellation ends the loop. Only MCP receives the maintenance flag; web workers retain their ordinary fallback readers.

This maintains shared data rather than individual pages or Job Rooms. No cold benchmark job, benchmark-only agent profile or arbitrary user wallet is preloaded. There is no change to workload, admission settings, targets, freshness intervals, observation dates, Redis retention, quote expiry or transaction checks. Successful reads do not re-date existing observations. Failed reads never publish an empty replacement. A stopped refresher retains the same fallback behavior as before.

The operator-wallet set also shares its complete measured result across workers, preserving its original ten-minute freshness from the query's start. Its unchanged SQL uses the existing bounded, read-only catalogue reader and fenced cold coordination. A process adopting a peer's set keeps that original date; it cannot start a new ten-minute lifetime. Missing or expired data requires a successful read. This is a display classification; hire eligibility and financial execution continue to use their existing exact reads.

Projection leases identify their producer within the same Linux boot and PID namespace. A peer may reclaim a lease only when a zero-signal existence check confirms that process has exited; deletion still compares the complete ownership token atomically. Live processes, other namespaces, uncertain permissions and older lease formats retain normal expiry. This prevents a stopped producer leaving cold readers waiting for a full lease after a deployment. The locality value is server metadata, not signing authority.

Unit tests cover bounded concurrency, complete-body failures, cancellation, non-overlapping cycles, loopback destinations, absence of money writes or individual job preloads, and original-date preservation and recovery for operator sets. Existing marketplace scope, quote expiry, counts, storefront, campaign and transaction tests remain required. Full CI, one pinned build, compiled and public acceptance, the normal deployment gate and an unchanged guarded external retest are separate gates. This candidate alone is not a latency or capacity pass.
