What is checked, and to what tolerance

FieldBoundWhat it means
currentTick±0 ticksReported current tick must equal the pool tick at the pinned block, exactly.
proposedTickSpacingbooleanEvery proposed tick must be an exact multiple of the pool’s tickSpacing.
policyRange±1 tick spacingsProposed bounds must match the range implied by the policy SUPPLIED IN THE TEST CASE, within one tick spacing.
amounts±0.5 %Proposed token amounts must satisfy the V3 liquidity formula within this tolerance.
inRangebooleanThe in-range boolean must match the chain.
distanceToBound±0.5 percentage pointsDistance to the nearest bound, in price terms.
slippageBoundbooleanA slippage bound must be stated, as a positive number.

Every bound carries a reason, not just a number. A tolerance nobody can justify is a tolerance that will be widened the first time it is inconvenient.

  • currentTickThe tick is a single integer read from slot0 at a fixed block. There is no ambiguity and therefore no tolerance.
  • proposedTickSpacingThe pool contract reverts on a tick that is not a multiple of its spacing, so a plan that violates this is not merely suboptimal, it is unexecutable. This is the single highest-signal check in the set and the most common failure in naive agents.
  • policyRangeThere is no objectively correct V3 range in the abstract, so the case supplies the policy and we check compliance with it. One spacing of slack is the minimum the pool’s own granularity permits: the ideal tick is rarely itself a valid multiple.
  • amountsThe formula is exact, but agents legitimately round for slippage and gas. 0.5% admits sane rounding while rejecting an agent that has not actually run the maths.
  • inRangeDerived from tickLower <= tick < tickUpper. One right answer.
  • distanceToBoundDerived arithmetic from the tick and the two bounds. The half-point band absorbs differences in rounding convention, not differences in method.
  • slippageBoundAn execution plan with no slippage bound is unsafe to sign regardless of how good its range is. We check only that a bound is stated, never whether the chosen value was wise — that is a Ledger question.

The ground-truth method

The expected values are computed by us from chain state at a pinned block, never taken from a third party. A case is captured immediately before a run because BSC keeps roughly 64 blocks of state — about 29 seconds — so a case captured earlier could not be read by the agent under test or by us.

What this test refuses to grade

  • Whether the chosen range is the wisest availableThere is no objectively correct V3 range in the abstract. The test case supplies a policy and we check compliance with it; the quality of the policy is a Ledger question.

A standard is defined as much by what it refuses to grade as by what it grades. Every one of these is a judgement question and belongs in the Ledger, against a rubric registered before anyone has seen an answer.
